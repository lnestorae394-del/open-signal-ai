# Обновление уже развёрнутого сервиса на Render

Переменные окружения и проект Firebase не меняются: новые функции используют те же `ENCRYPTION_KEY`, `SESSION_SECRET`, `ADMIN_SETUP_TOKEN` и `FIREBASE_SERVICE_ACCOUNT`. Данные в Firestore сохраняются: старые настройки ботов автоматически дополняются новыми полями при чтении (партнёрская ссылка из старого поля переносится в новый раздел).

## 1. Заменить файлы в папке проекта

1. Распакуйте новый архив во временную папку.
2. Скопируйте всё его содержимое в вашу папку `open-signal-ai` с заменой файлов. Папки `.git` и файл `.env` (если есть) не трогайте.
3. Удалите из вашей папки файлы, которых больше нет в архиве. Проще всего так (выполнять в папке проекта на Mac):

```bash
cd ~/open-signal-ai
git status
```

Команда покажет изменённые и удалённые файлы. Если в списке есть `.env` или `*firebase-adminsdk*.json` — остановитесь: этих файлов не должно быть в git.

## 2. Создать package-lock.json и проверить у себя (обязательно один раз)

В архиве нет `package-lock.json`: его невозможно честно создать без доступа к npm. Он создаётся у вас одной командой. После этого все установки, включая Render, берут ровно те же версии пакетов.

```bash
cd ~/open-signal-ai
npm install
npm run check
```

- `npm install` скачает пакеты и создаст файл `package-lock.json`.
- `npm run check` проверит, что lock-файл совпадает с `package.json`, затем выполнит строгую проверку TypeScript, сборку и все тесты. В конце должно быть `# fail 0`.

Если `check` сообщает «package-lock.json does not match» — ещё раз выполните `npm install`.

## 3. Отправить в GitHub

```bash
git add -A
git status            # в списке должен быть package-lock.json; не должно быть .env и *adminsdk*.json
git commit -m "Lock dependencies, repeat deposits never merged, redirect check"
git push
```

Render сам начнёт новый деплой (около 3 минут). Если сборка или проверка `/health` не пройдёт, Render оставит работать прежнюю версию.

## 4. Проверить после деплоя

1. Откройте `https://<ваш-адрес>/health` — должно быть `"status":"ok"`, `"persistentStorage":true` и `"signalEngine":"training"`.
2. Админка → **Обзор** → блок «Индексы базы данных». Новые индексы (сигналы, история postback, ошибки) создаются автоматически при запуске, обычно за несколько минут. Пока индекс строится, разделы «История» и «Ошибки интеграции» могут быть пустыми.
3. Админка → **Postback и депозиты** → **Источник**: если глобального источника ещё нет — создайте его, скопируйте три URL и вставьте их в кабинет Pocket Partners. Подробно: [global-pocket-partners-postback.md](global-pocket-partners-postback.md). **Секрет показывается один раз.**
4. Админка → **Боты** → каждый бот → **Партнёрская ссылка**: в ссылке должен быть `{click_id}` в том параметре, который Pocket Partners возвращает в postback. Нажмите **Проверить ссылку**.
5. Админка → **Академия** → «Скопировать курс», если хотите редактировать стартовые уроки (без этого пользователи видят встроенный курс).
6. Админка → **Сигналы**: проверьте пары, время сделки, паузу, лимит и переключатель «только после подтверждённого FTD».
7. Откройте бота в Telegram → `/start` → кнопка приложения. Новый пользователь должен увидеть шаг 1 онбординга.

## Что важно знать

- **Онбординг теперь обязателен для всех.** Пользователи, которые раньше открывали приложение без регистрации, тоже увидят шаг 1. Те, у кого Trader ID уже привязан и есть FTD ≥ $10, пройдут дальше автоматически.
- Данные Firestore не удаляются. Старые коллекции (`simulation_history`, `market_*`) больше не используются, но остаются в базе.
- Старый переключатель модуля «Привязка аккаунта» убран: онбординг включён всегда.
