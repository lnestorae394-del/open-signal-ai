# Глобальный postback Pocket Partners

Один источник postback обслуживает все боты. Регистрация, первый депозит (FTD) и повторный депозит приходят на один адрес; к какому боту и пользователю относится событие, сервер определяет по `click_id`.

## 1. Партнёрская ссылка каждого бота

Админка → **Боты** → бот → вкладка **Партнёрская ссылка**. В ссылку подставляются:

| Метка в ссылке | Что подставит сервер |
|---|---|
| `{click_id}` | личный код пользователя (128 случайных бит, живёт 90 дней) — **обязателен** |
| `{bot_id}` | ID бота |
| `{partner_id}` | ID партнёра из настроек бота |

Через какой параметр трекинговой ссылки Pocket Partners передаёт ваш `click_id` обратно в postback, нужно посмотреть **в кабинете Pocket Partners** (раздел ссылок / Sub ID). Название параметра здесь не угадывается. Пример формы ссылки: `https://…/register?<параметр_из_кабинета>={click_id}`.

После сохранения нажмите **Проверить ссылку**: админка покажет, есть ли `{click_id}`, https и куда ведёт редирект. **Сохраняется ли параметр после всех редиректов Pocket Partners, автоматически проверить нельзя** — это проверяется одной тестовой регистрацией (раздел 4).

## 2. Источник postback

Админка → **Postback и депозиты** → **Источник** → «Создать глобальный источник». Значения по умолчанию заполнены под Pocket Partners:

| Поле | Значение | Макрос Pocket Partners |
|---|---|---|
| Секрет | параметр `key` | — (секрет показывается один раз) |
| Тип события | параметр `event`: `reg`, `ftd`, `dep` | — (вы пишете значение сами в каждом URL) |
| Click ID | `click_id` | `{click_id}` |
| Trader ID | `trader_id` | `{trader_id}` |
| Сумма | `sumdep` | `{sumdep}` |
| Валюта, ID события, время | пусто | не используются: у Pocket Partners таких макросов не найдено |

После создания админка покажет три готовых URL с кнопкой «Скопировать» — по одному на регистрацию, FTD и повторный депозит. Их нужно вставить в кабинете Pocket Partners для соответствующих событий. Форма:

```
https://ВАШ-АДРЕС/postback/SOURCE_ID?key=СЕКРЕТ&event=reg&click_id={click_id}&trader_id={trader_id}
https://ВАШ-АДРЕС/postback/SOURCE_ID?key=СЕКРЕТ&event=ftd&click_id={click_id}&trader_id={trader_id}&sumdep={sumdep}
https://ВАШ-АДРЕС/postback/SOURCE_ID?key=СЕКРЕТ&event=dep&click_id={click_id}&trader_id={trader_id}&sumdep={sumdep}
```

> Макросы `{click_id}`, `{trader_id}`, `{sumdep}` (и флаги `{reg}`, `{ftd}`, `{dep}`) взяты из двух независимых открытых описаний настройки postback Pocket Partners (инструкция MVP Project и обзор affdays.com); официальной публичной документации Pocket Partners не найдено. В кабинете названия параметров в URL можно переименовать (например, `clickid={click_id}`), макросы при этом те же. Можно ли дописать в URL свои фиксированные параметры `key=…` и `event=…` — проверьте в поле Data format кабинета: без `key` сервер отвечает 401 и пишет ошибку в «Ошибки интеграции». Перед запуском сверьте их со списком макросов в вашем кабинете. Если названия отличаются — поменяйте их в URL; код менять не нужно.

## 3. Как сервер обрабатывает событие

1. Проверка секрета (сравнение за постоянное время), формата и типа события. Ошибки попадают в **Ошибки интеграции**.
2. Поиск `click_id` → бот и пользователь. Если `click_id` нет, он неизвестен или истёк — ответ 400, событие никому не засчитывается, в **Ошибки интеграции** пишется `UNKNOWN_CLICK`.
3. **Регистрация:** если пользователь уже ввёл этот Trader ID — привязка сразу; иначе событие ждёт, пока он введёт Trader ID. Чужой Trader ID (событие пришло по другому `click_id` или другому боту) отклоняется.
4. **FTD / повторный депозит:** засчитываются только пользователю, которому принадлежит `click_id` события, и только в его боте. Каждое финансовое событие пишется в журнал аудита (`finance.ftd`, `finance.redeposit`).
5. **Проверка депозита:** «Подтверждён» — сумма ≥ $10 в USD (если валюта не передана, считается USD); «Проверяется» — нет суммы или валюта не USD; «Ошибка» — сумма меньше $10 или конфликт сумм; «Ожидается» — событий ещё нет.

### Повторная доставка и одинаковые депозиты
Pocket Partners не передаёт ID события и время депозита (в открытых описаниях поля postback: `click_id`, `trader_id`, `sumdep` и флаги `reg`, `ftd`, `dep`). Поэтому:

| Событие | Как распознаётся повтор |
|---|---|
| Регистрация | по Trader ID — одна регистрация на Trader ID; повтор получает 200 и «Доставок +1» |
| FTD | по Trader ID — один первый депозит на Trader ID, даже если партнёр пришлёт разные ID событий |
| Повторный депозит с ID события или временем (если когда-нибудь появятся) | по этому ID / времени |
| **Повторный депозит без ID и времени (Pocket Partners)** | **не объединяется**: каждый запрос — отдельный депозит |

Почему так: повторная доставка и второй настоящий депозит на ту же сумму выглядят одинаково. Объединять их по сумме значит терять настоящие депозиты, поэтому сервер **засчитывает каждый**. Если в течение 10 минут пришёл депозит с тем же Trader ID и той же суммой, он помечается «Возможный повтор». В «Ошибках интеграции» появляется `POSSIBLE_DUPLICATE`.

Администратор (владелец или менеджер с правом управления привязками) может в **Истории** нажать **Исключить** на таком событии, указав причину. Событие не удаляется, сумма пересчитывается, в журнал пишется `finance.event_excluded`. Кнопка **Вернуть в учёт** отменяет это решение (`finance.event_restored`).

На онбординг повторные депозиты не влияют: шаг 3 зависит только от FTD.

FTD, пришедший повторно **с другой суммой**: сохраняется первая сумма, депозит получает статус «Ошибка», в журнал пишутся `finance.amount_conflict` и ошибка `AMOUNT_CONFLICT`.

Повторный депозит без события FTD (FTD-postback потерялся): шаг 3 показывает «Проверяется», приложение не открывается, пока не придёт FTD или поддержка не разберётся.

### click_id
Новые `click_id` — 32 символа `0-9a-f` (128 случайных бит). Такой код переживает трекеры, которые меняют регистр или допускают в Sub ID только буквы и цифры. Если партнёр вернёт код заглавными буквами, он всё равно найдётся. Коды старого формата (22 символа), выданные до обновления, продолжают работать.

**Проверить ссылку** в админке проходит всю цепочку редиректов (до 8 шагов) и на каждом шаге показывает, виден ли тестовый `click_id` в адресе. Если на последнем шаге его не видно, это ещё не ошибка: трекер может хранить его у себя. Окончательно это подтверждает только тестовая регистрация (раздел 4).

## 4. Проверка перед запуском

1. Откройте бот в Telegram → «Зарегистрироваться» → пройдите регистрацию тестовым аккаунтом.
2. Админка → **Postback и депозиты** → **История**: должно появиться событие «Регистрация» со статусом «Привязано» или «Ждёт ввода Trader ID». Если его нет — смотрите вкладку **Ошибки интеграции** и проверьте, что параметр с `click_id` доходит до postback.
3. Введите Trader ID в Mini App — шаг 2 должен пройти.
4. Сделайте депозит от $10 — шаг 3 должен стать «Подтверждён».

Не используйте адреса и секреты HiddenDinox Academy в этом проекте.
