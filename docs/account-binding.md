# Онбординг и привязка Telegram ID ↔ Trader ID

Код: `apps/api/src/binding/` (`service.ts`, `onboarding.ts`, `postback.ts`, `state-machine.ts`). Тесты: `apps/api/test/binding.test.ts` и `platform.test.ts`.

## Три шага (обязательны, обходов нет)

| Шаг | Что видит пользователь | Когда шаг пройден |
|---|---|---|
| 1. Регистрация | «Откройте торговый счёт» → «Зарегистрироваться» (партнёрская ссылка с личным `click_id`) | пользователь вернулся после перехода |
| 2. Trader ID | поле Trader ID → «Привязать аккаунт» | сервер нашёл postback `registration` с этим Trader ID **и** `click_id` этого пользователя в этом боте |
| 3. Депозит | статус: Ожидается / Проверяется / Подтверждён / Ошибка, сумма | postback `ftd` ≥ $10 (если в админке → Сигналы включено «только после FTD»; по умолчанию включено) |

Статус хранится в `users` в Firestore, поэтому после перезапуска и на другом устройстве пользователь продолжает с того же шага. Пройденный онбординг (`onboardingCompletedAt`) не сбрасывается.

## Проверка Trader ID (шаг 2)
1. Формат — по шаблону бота (по умолчанию `^[A-Za-z0-9_-]{3,64}$`, меняется в настройках бота).
2. Регистрация ещё не пришла → `REGISTRATION_NOT_CONFIRMED`. Заявка сохраняется: если postback придёт позже по `click_id` этого пользователя, привязка произойдёт автоматически и пользователь окажется на шаге 3.
3. Регистрация пришла по чужому `click_id` или в другом боте → `CLICK_MISMATCH`.
4. Trader ID уже привязан к другому Telegram ID → `TRADER_ID_TAKEN`. Уникальность гарантирует документ-замок `trader_bindings/{botId}_{sha256(traderId)}`, создаваемый в транзакции.
5. При ошибке Mini App показывает понятный текст и «Попробовать ещё раз» → возврат к шагу 1 без потери состояния. Последняя ошибка видна администратору (Пользователи → «Проверка»).

Никаких фиктивных подтверждений: шаги 2 и 3 проходят только по событиям postback.

## Правила
- Вход только через Telegram (проверенная initData); вне Telegram Mini App показывает только ссылку на бота.
- `click_id` — 128 случайных бит, не вычисляется из Telegram ID, живёт 90 дней.
- Событие по чужому `click_id` никогда не привязывает пользователя и не засчитывает ему депозит.
- Пользователь не может сам сменить привязанный Trader ID; администратор может — с причиной и записью в `audit_logs` (Trader ID в журнале маскируется).
- Старые postback-источники отдельных ботов (если были созданы раньше) продолжают работать; новые подключения — через глобальный источник ([global-pocket-partners-postback.md](global-pocket-partners-postback.md)).
