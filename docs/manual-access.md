# Ручное управление пользователем

## Кнопки «Выдать доступ» и «Забрать доступ»

Админка → **Пользователи**. В каждой строке: пользователь и Telegram ID, Trader ID, Click ID, сумма депозитов, статус регистрации, статус доступа, источник доступа (депозит / ручная выдача), действия.

- **Выдать доступ** — сразу открывает пользователю сигналы. Не нужны регистрация, депозит, FTD, `click_id` или Trader ID. Доступ сохраняется после перезапуска и на другом устройстве. Статус — «Выдан вручную».
- **Забрать доступ** — снимает только ручное исключение. Если у пользователя подтверждён депозит (обычный доступ), доступ остаётся. Если нет — сигналы закрываются, и пользователь возвращается на свой реальный шаг онбординга. Регистрация, Trader ID, Click ID и история депозитов не трогаются.

Перед действием нужно подтверждение с причиной. Статус в строке обновляется сразу, без перезагрузки страницы; сверху появляется сообщение об успехе или ошибке.

Правило доступа одно и проверяется на сервере (`apps/api/src/binding/access.ts`): `доступ = ручной доступ ИЛИ обычный доступ (онбординг пройден)`. Пользователь с ручным доступом может сам завершить подключение: Профиль → «Подключить аккаунт». После подтверждённого депозита доступ сохранится и без ручного исключения.

## Карточка пользователя

Кнопка **Управление** в строке открывает карточку:

- Telegram ID, имя и username, бот, Trader ID;
- статусы: регистрация, привязка, проверка, депозит, сумма подтверждённого депозита;
- доступ к сигналам: обычный или выданный вручную; кто, когда и с какой причиной выдал или отозвал доступ;
- последнее ручное действие с этим пользователем.

Статус в колонке «Доступ»: «Ожидает регистрации», «Ожидает Trader ID», «Проверка», «Ожидает депозит», «Подтверждён», «Доступ выдан вручную», «Доступ отозван», «Требуется проверка». Фильтр **«Доступ выдан вручную»** показывает только пользователей с ручным доступом.

## Действия

Каждое действие — отдельная кнопка. Перед выполнением нужно указать причину (от 5 символов) и нажать «Подтвердить». Сервер проверяет право **«Управление привязками»** для этого бота (у владельца оно есть всегда), выполняет изменение в транзакции и пишет запись в журнал аудита с вашим именем и причиной. Финансовые события и история регистрации не удаляются и не меняются.

| Ситуация | Кнопка | Что меняется | Что НЕ меняется |
|---|---|---|---|
| Технический сбой, пользователь не может пройти онбординг | **Выдать доступ** | только отдельное разрешение `manualAccess` | депозит, Trader ID, состояние привязки, статус онбординга, события postback |
| Сбой устранён | **Забрать доступ** | разрешение снимается, остаётся история (кто, когда, почему выдал и отозвал) | если онбординг пройден обычным путём, доступ остаётся |
| Застрял на регистрации: зарегистрировался, но приложение не перешло к шагу 2 | **Перевести на ввод Trader ID** | отметки шагов 1–2 | привязка, депозит |
| Нужно пройти онбординг заново | **Начать онбординг заново** | отметки шагов 1–2 сбрасываются | регистрации и депозиты у партнёра, события postback |
| Trader ID не проходит проверку из-за сбоя, а вы убедились, что аккаунт пользователя | **Привязать Trader ID вручную** (прежний механизм `binding/bind`) | привязка Trader ID | события postback; депозит засчитывается только по реальным событиям партнёра |
| Привязан не тот Trader ID | **Отвязать Trader ID** (прежний механизм `binding/reset`) | привязка снимается, пользователь снова вводит Trader ID | события и сохранённая сводка депозита |
| Застрял на проверке депозита | **Пересчитать депозит** | сводка депозита пересчитывается по уже полученным событиям партнёра | ничего не подтверждается без реального события от Pocket Partners |

«Перевести на ввод Trader ID» и «Начать онбординг заново» доступны только пока Trader ID не привязан. Для привязанного пользователя используйте «Отвязать Trader ID» или «Привязать Trader ID вручную».

## Как работает ручной доступ

Право открыть сигналы проверяет сервер, а не только интерфейс (`apps/api/src/binding/access.ts`). Доступ есть, если онбординг пройден обычным путём **или** администратор выдал ручной доступ. Ручной доступ не ставит отметку «онбординг пройден», не подтверждает депозит и не создаёт событий. В Mini App пользователь с ручным доступом попадает сразу на экран сигналов; академия и профиль тоже открыты.

Пользователь, который однажды прошёл онбординг обычным путём, сохраняет доступ даже после отвязки Trader ID — так было и раньше.

Новые поля пользователя `manualAccess` и `manualAccessActive` у существующих пользователей просто отсутствуют. Миграция не нужна.
