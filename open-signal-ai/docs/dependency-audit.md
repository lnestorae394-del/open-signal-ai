# Аудит зависимостей

## Правила
- `npm audit fix --force` **не используется**: он может молча поставить мажорные версии с несовместимыми изменениями.
- Для каждой уязвимости определяем: пакет, путь (какая наша зависимость его тянет), попадает ли он в рабочий сервер или только в инструменты разработки, и есть ли безопасная версия в пределах текущей мажорной.

## Команды
```bash
npm audit                 # полный отчёт
npm run audit:prod        # только то, что попадает на рабочий сервер (без инструментов разработки)
npm run audit:report      # отчёт + файл audit-report.json (в git не попадает)
npm ls <имя-пакета>       # путь: какая наша зависимость тянет уязвимый пакет
```

## Сделано на этапе 1 (исправления)
- Из `apps/api` удалён неиспользуемый `firebase-admin`: в коде он не импортировался, а тянул большое дерево транзитивных зависимостей. Он вернётся на этапе 2 вместе с адаптером Firestore — в актуальной версии и после отдельного аудита.

## Как читать результат
| Где пакет | Риск |
|---|---|
| попадает в `npm run audit:prod` | влияет на рабочий сервер → исправляем обязательно |
| только dev (vite, esbuild, tailwind) | затрагивает только локальный dev-сервер на вашем компьютере; исправляем обновлением в пределах мажорной версии |
