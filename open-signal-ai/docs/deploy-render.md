# Развёртывание на Render + Firebase

Время: около 20 минут. Бесплатно: Firestore на тарифе Spark и Render Free. Платных шагов в инструкции нет.

Ограничение бесплатного Render: после 15 минут без запросов сервер засыпает, первый запрос после этого занимает 30–60 секунд, и бот в это время отвечает с задержкой. Данные при этом не теряются: они хранятся в Firestore. Постоянная работа без засыпания — тариф Starter, $7 в месяц. Включайте его только если решите сами.

---

## Шаг 1. Firebase: база данных

1. Откройте https://console.firebase.google.com и нажмите **Создать проект** (Create a project).
2. Название — например `open-signal-ai`. Google Analytics можно выключить. Нажмите **Создать проект**.
   Не используйте проект HiddenDinox — нужен новый, отдельный.
3. В левом меню: **Build → Firestore Database → Create database**.
4. Режим: **Standard edition**, затем **Production mode**. Регион: `eur3 (europe-west)`. Нажмите **Create**.
   Регион потом изменить нельзя.

## Шаг 2. Firebase: ключ доступа для сервера

1. В Firebase нажмите шестерёнку рядом с **Project Overview → Project settings**.
2. Вкладка **Service accounts** → кнопка **Generate new private key** → **Generate key**.
3. Скачается файл `.json`. Это секрет: не отправляйте его в чаты и не кладите в папку проекта.
4. Ключ должен уметь создавать индексы. Откройте https://console.cloud.google.com/iam-admin/iam, вверху выберите свой проект. Найдите строку с адресом `firebase-adminsdk-...@...iam.gserviceaccount.com`, нажмите карандаш → **Add another role** → **Cloud Datastore Index Admin** → **Save**.
   Без этой роли сервер работает, но индексы придётся создать вручную. Админка покажет это в блоке «Индексы базы данных».

## Шаг 3. GitHub

Загрузите проект в **приватный** репозиторий по инструкции [github-first-push.md](github-first-push.md).

## Шаг 4. Render

1. Откройте https://dashboard.render.com, нажмите **New → Blueprint**.
2. Подключите GitHub, если Render попросит, и выберите репозиторий `open-signal-ai`.
3. Render прочитает файл `render.yaml` и покажет сервис `open-signal-ai`. Он запросит одно значение: **FIREBASE_SERVICE_ACCOUNT**.
4. Откройте скачанный на шаге 2 `.json` в текстовом редакторе, выделите **всё** содержимое, скопируйте и вставьте в это поле. Вставлять нужно только в Render, больше никуда.
5. Нажмите **Apply**. Сборка занимает 2–4 минуты.

Render сам создаст `ENCRYPTION_KEY`, `SESSION_SECRET` и `ADMIN_SETUP_TOKEN` и сохранит их между деплоями.

> Сделайте резервную копию `ENCRYPTION_KEY`: Render → сервис → **Environment** → значок глаза → сохраните в менеджер паролей. Без этого ключа сохранённые токены ботов нельзя расшифровать.

## Шаг 5. Проверка

1. В Render откройте сервис. Вверху будет адрес вида `https://open-signal-ai-xxxx.onrender.com`.
2. Добавьте к нему `/health` и откройте в браузере. Должно быть `"status":"ok"` и `"persistentStorage":true`.
   Если деплой упал, откройте вкладку **Logs**. В ней будет одна понятная строка с именем переменной или причиной (например, «Firestore is not reachable»).

## Шаг 6. Создание владельца

1. Откройте `https://<ваш-адрес>.onrender.com/admin/`.
2. Нужен токен настройки: Render → сервис → **Environment** → `ADMIN_SETUP_TOKEN` → значок глаза → скопируйте.
3. Вставьте его на странице, введите свой e-mail и пароль (от 10 символов) → **Создать и войти**.
   Это делается один раз. Потом страница создания владельца больше не открывается.

## Шаг 7. Первый бот

1. В Telegram откройте @BotFather → `/newbot` → придумайте имя и username → скопируйте токен.
2. В админке: **Боты → Подключить бота**, вставьте токен, заполните название и описание → **Подключить бота**.
3. Сервер сам настроит webhook, описание, кнопку меню Mini App и аватар (если загрузите JPEG).
4. Откройте бота в Telegram и отправьте `/start`. Появится кнопка для открытия Mini App.

Новые боты добавляются так же, без изменения кода и без нового деплоя.

## Свой домен (необязательно)

1. Render → сервис → **Settings → Custom Domains → Add**, следуйте подсказкам DNS.
2. Render → **Environment → Add Environment Variable**: `PUBLIC_URL` = `https://ваш-домен`.
3. **Save Changes**. После перезапуска сервер сам перенастроит webhook всех ботов на новый адрес.

## Обновления

Каждый push в ветку `main` запускает новый деплой. Если сборка или проверка `/health` не прошла, Render оставляет работать предыдущую версию. Данные хранятся в Firestore и не зависят от деплоев.

## Переменные окружения

| Переменная | Откуда | Назначение |
|---|---|---|
| `NODE_ENV` | render.yaml | `production` |
| `FIREBASE_SERVICE_ACCOUNT` | вы, шаг 4 | доступ к Firestore |
| `ENCRYPTION_KEY` | Render генерирует | шифрование токенов ботов и секретов (AES-256-GCM) |
| `SESSION_SECRET` | Render генерирует | подпись сессий Mini App |
| `ADMIN_SETUP_TOKEN` | Render генерирует | одноразовое создание владельца |
| `PORT`, `RENDER_EXTERNAL_URL` | Render сам | порт и публичный адрес |
| `PUBLIC_URL` | необязательно | свой домен |
| `CORS_ORIGINS` | необязательно | внешние сайты, которым разрешено обращаться к API |
| `ENCRYPTION_KEY_PREVIOUS` | при ротации ключа | старый ключ для чтения прежних данных |
